# 病例：一个居中窗口，废掉 14 轮研究

> 这是 `lookahead-guard` 的由来。所有数字来自一次真实的研究事故。

## 一、事情是怎么发生的

研究里有一个特征 `C1`，定义是"当前价在过去 20 日区间中的位置"：

```python
from scipy.ndimage import minimum_filter1d, maximum_filter1d

def C1(close):
    mn = minimum_filter1d(close, 20, axis=0, mode="nearest")
    mx = maximum_filter1d(close, 20, axis=0, mode="nearest")
    return (close - mn) / np.maximum(mx - mn, 1e-12)
```

写得干净、可读，跑得通，而且**它让结果变好了**。

问题在于：`scipy.ndimage` 的 `filter1d` 族，默认 `origin=0` 的意思是**居中**，
不是尾随。`size=20` 的实际窗口是 `[t-10, t+9]` —— **含未来 9 个交易日**。

也就是说，这个特征在 t 时刻"知道"了未来 9 天的最高价和最低价。
`C1 = 1` 的真实含义不是"价格在区间顶部"，而是**"它即将上涨"**。

## 二、代价

| 项 | 修窗前 | 修窗后 |
|---|---|---|
| R3 检验净收益 | **+5.30%** | **−0.39%** |
| 账户层 20 个月 | **+73.47%** | **+5.37%** |

**第 395–408 枪，共 14 轮研究，全部作废。**

## 三、最值得记住的一点

在这 14 轮里，我们做过 **8 项证伪检查，全部通过**。

它们之所以全部通过，是因为**它们跑在同一个被污染的对象上**——
缺陷写在被测物内部，外部的证伪闸门就查不出来。这是一个方法论级别的教训：

> **证伪闸门无法发现写进被测物里的缺陷。**

所以 `lookahead-guard` 的 B 层不是又一项证伪检查。它**直接扰动被测物**：
把 t 之后的数据加随机噪声，看 t 及以前的输出变不变。变了 ⇒ 它偷看了未来。
这个判据不依赖收益、不依赖假设、不依赖任何"证伪项"，因此不会被同样的方式骗过。

## 四、修法

一行：

```python
mn = pd.Series(close).rolling(20, min_periods=1).min().to_numpy()
mx = pd.Series(close).rolling(20, min_periods=1).max().to_numpy()
```

`pandas.rolling` 默认就是尾随窗口。改完再跑一遍：

```console
$ lookahead-guard blind --module c1_centered.py:C1 --csv prices.csv --col close
  FAIL  未来函数: 35 格改变，最晚受污染的 t = 30

$ lookahead-guard blind --module c1_trailing.py:C1 --csv prices.csv --col close
  PASS  未来盲: 扰动 t 之后的数据, t 及以前的输出一格未变
```

## 五、这个教训为什么必须写成代码

事故当天的结论原话是「**这一步 10 秒，能省 14 把枪**」。
但那条教训当时**只是一条笔记，不是一道闸门**——只要下次再手写一个滚动原语，
同一个坑会以同样的方式重开，而且还是会更好看、还是会通过所有证伪检查。

**所以把它变成了代码。** 见本仓库 A / B / C / D 四层。
